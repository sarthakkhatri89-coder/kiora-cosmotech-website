Prepared from live crawl evidence + repository source code review

Executive Summary

Kiora CosmoTech now has a materially stronger SEO foundation than a generic brochure site. The live website is crawlable, the sitemap is valid, the major commercial pages are indexable, schema is present on key landing pages, and the content model is significantly deeper than the average private-label manufacturing website. The main blockers are no longer basic metadata or routing. The biggest blockers are commercial: lead capture is not functional, analytics are absent, legal trust pages are missing, and schema consistency across the page system is uneven.

No material deploy mismatch was detected between the live site and the current codebase on the sampled routes. The issues documented here are implementation decisions present in both environments, not stale deployment artifacts.

Top 5 Findings

  1. The quote form currently does not send enquiries anywhere.
  2. No analytics or conversion tracking implementation was detected.
  3. The site still self-canonicalizes to the Vercel subdomain.
  4. Privacy / Terms trust-floor pages are missing.
  5. Shared commercial pages use lighter schema than custom landing pages, and the hair serum page still duplicates Service schema.

Live Website Findings

  • Robots: live at /robots.txt, permissive, includes sitemap and host.
  • Sitemap: live at /sitemap.xml, 68 URLs, valid lastmod entries.
  • Status codes: key commercial pages return 200 and are prerendered from Vercel cache.
  • Metadata: most key pages are now in a cleaner range, but hair serum and several blogs still overrun ideal snippet lengths.
  • Heading structure: sampled key pages all use one H1.
  • Schema: root layout emits Organization + WebSite; custom pages add richer schema; shared pages remain lighter.

Source Code Findings

  • Framework: Next.js 15 App Router, static rendering, metadata via helper in lib/seo.ts.
  • Canonical source: driven by siteConfig.url in data/siteConfig.ts.
  • Schema helpers: centralized in lib/schema.ts.
  • Shared page renderers: components/ContentPageRenderer.tsx and components/ProductPageRenderer.tsx.
  • Tracking: none detected in source.
  • Lead form: components/QuoteForm.tsx uses a local state-only submit flow.

Live vs Source Mismatch Assessment

Result: no major deploy drift was detected on the sampled pages. The live site reflects the current source on metadata, sitemap behavior, and the main custom product pages. The remaining issues are shared implementation issues, not environment mismatch bugs.

The only notable risk is strategic rather than technical drift: if the business intends to rank a branded custom domain instead of the Vercel subdomain, both live and source must be updated together.
